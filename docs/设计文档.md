设计一个简单的初始Agent

目录包括以下内容：
- prompts: 存放基础提示词
- tools: 存放基础工具
- utilities: 存放Agent的“基础设施”

### Tools:
所有工具必须派生自同一个基类，包含以下属性：
    - name: 工具名称, str
    - guide: 提供给Agent的工具使用指南, str
    - parameters: 工具参数，dict, Optional. 例如对于Bash而言，参数是命令行参数，对于Edit而言，参数是编辑的目标文件和内容
    - returns: 工具返回值，dict, Optional. 例如对于Bash而言，返回值是命令执行结果
    - result: 工具调用结果, boolean
    - start_time: 工具调用开始时间, datetime
    - end_time: 工具调用结束时间, datetime

初始工具包含Edit和Bash两种：
Edit用于查看文件或目录、创建文件、整体覆盖文件，没有局部替换、按行修改等功能，修改文件需要提供完整内容
Bash用于执行命令
每一个工具都应该放在各自独立的文件夹中，并且在Agent启动时自动扫描和加载

### Prompts:
基础提示词包含两个大类：
1. 任务执行提示词：引导Agent完成代码生成任务
2. 自我改进提示词：引导Agent完成自优化任务
根据任务类型不同，Agent使用不同的提示词

#### 任务执行提示词(prompts/common/)：
包含以下5个板块：
1. 执行效率引导(prompts/common/01_efficiency_guide.md)：引导Agent高效的使用工具调用并高效的完成任务
2. 代码探索引导(prompts/common/02_exploration_guide.md)：引导Agent在代码生成前进行代码探索，理解现有代码库
3. 代码生成引导(prompts/common/03_code_generation_guide.md)：指导Agent进行代码生成
4. 代码验证引导(prompts/common/04_validation_guide.md)：指导Agent生成测试用例或通过其他检查方式（例如pylint等）验证代码正确性，并在代码出现错误时进入`验证-修复`流程

注意：以上4个提示词再初始时应该遵循简单且必要的原则，这4个提示词应该由Agent在未来逐步优化

5. 工具调用引导：Agent初始化时有所有注册的工具的name和guide自动产生

完整提示词由以上4个板块+骨架+用户提示词拼接而成，具体而言：
``` markdown
You are a coding agent. Please finish the user's request based on the following instructions.
[执行效率引导]

[代码探索引导]

[代码生成引导]

[代码验证引导]

User: [用户提示词]

There are the available tools you can use:
[工具列表]
```

#### 自我改进提示词(prompts/optimization/)：
与任务执行提示词需要组装不同，自我改进提示词每一个都是独立的，并且在初始时即为完备状态，包含5个部分：
1. 效率优化提示词(prompts/optimization/01_efficiency_optimization.md)
2. 代码探索优化提示词(prompts/optimization/02_exploration_optimization.md)
3. 代码生成优化提示词(prompts/optimization/03_code_generation_optimization.md)
4. 代码验证优化提示词(prompts/optimization/04_validation_optimization.md)
5. 更改合并提示词(prompts/optimization/05_assemble_guide.md) 引导Agent根据奖励函数的得分进行优化

这些提示词应该包含这些必要的信息：
- 需要优化的目标
- 优化的对应的奖励函数的计算公式
- 告知Agent可以增加/修改/删除工具，并提供工具编写说明
- 告知Agent可以增加/修改/删除提示词，并提供提示词的组织形式说明
这些提示词应该是受保护的只读状态，万一Agent的优化过程中尝试修改，应该将其复原

在1-4这4种提示词分别对应了处于优化模式的o_1/o_2/o_3/o_4模式，这些Agent：
- 工作目录就是当前需要优化的Agent的工作目录(复制一个去除Git历史信息的副本并在该目录下进行优化，这部分无需在Agent的代码中进行体现，将有后续调度器实现，这里只是补充背景信息以促进写出高质量的提示词)
- 完整的提示词组装：
``` markdown
f[对应的优化模式的提示词]

[前2次被采纳的optimization和前2次被拒绝的optimization对Agent代码的Diff+在样例上的处理后轨迹+奖励函数的得分]
```

而5号提示词对应了assemble模式，它的工作区存放着：1. 优化前Agent的代码仓, 2. 根据奖励函数公式得出被采纳的优化方向的代码仓（可能有多个）(这部分无需在Agent的代码中进行体现，将有后续调度器实现，这里只是补充背景信息以促进写出高质量的提示词)
assemble模式需要在优化前Agent的代码仓的基础上修改其代码，来整合被采纳的优化方向的代码仓的改动，最终生成一个新的Agent代码仓.

### utilities:
这一部分是对于Agent的其他要求：

1. 需要完整支持`OpenAI Compatible`, `OpenAI Response`, `Anthropic` 3类接口格式
2. 环境隔离：Agent只能阅读/修改自己工作区内的文件
3. 轨迹记录：Agent需要记录所有工具调用的轨迹
    轨迹包含2类节点，思考(think)和行动(action)
    思考节点包括Agent的思考内容，该次思考的Token消耗量，思考开始时间和结束时间
    行动节点包括上述工具调用的所有属性
4. 稳定性：Agent需要在远程API调用错误时进行重试，根据配置文件中的重试次数进行重试，超过重试次数后，Agent需要记录错误并退出
5. 交互性：具有TUI和无头（直接通过参数传入）2种模式
6. 历史聊天回话保存：保存历史会话，并通过/resume（TUI）或--resume（无头）参数进行恢复
7. 模式识别：通过参数传递，能够区分common/o_1/o_2/o_3/o_4/assemble 6种模式，并正确的调度提示词和设定工作目录

code_agent.py是整个代码库的唯一入口
